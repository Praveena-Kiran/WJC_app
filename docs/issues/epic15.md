## Issue #038 — `expo-speech` Japanese speech utility
**Epic:** audio | **Type:** port | **Priority:** P0 | **Size:** S
**Hard deps:** #004 (expo-speech installed) | **Soft deps:** none | **Stream:** F | **Assignee:** ____

### Goal
Replace web's `window.speechSynthesis` ja-JP utterance with `expo-speech`'s `speak(text, { language: 'ja-JP', rate: 0.8 })`. Expose a single `speakJapanese(text: string)` function via AppContext.

### Context for the AI agent
- `expo-speech` provides `Speech.speak(text, { language, pitch, rate, voice? })`. The `language` must be a BCP-47 tag: `ja-JP`.
- Android devices may lack a Japanese TTS engine; the app should still work (fallback to default voice, but note the issue in #058b).
- `speakJapanese` cancels any previous speech to avoid overlapping.

### Required deliverables
1. `mobile/src/lib/speech.ts`:
   ```ts
   import { Speech } from "expo-speech";
   export function speakJapanese(text: string) {
     Speech.stop();
     Speech.speak(text, { language: "ja-JP", rate: 0.8 });
   }
   ```
2. In `AppContext.tsx` (#013), add `speakJapanese` to the context value (call this function).
3. All listen buttons in KanaTrainer, KanaModal, Dictionary, KanjiBoard, Quiz, Kaiwa, PronunciationCoach call `speakJapanese(word/char/phrase)`.

### Technical notes
- On Android 6.0+ — Google TTS may need to be installed. If not available, `Speech.speak` still works but uses default voice. Show a small warning in #058b.
- On iOS, Japanese voices are pre-installed.
- `rate: 0.8` matches web's `utterance.rate = 0.8`.

### Validation / acceptance
- Call `speakJapanese("こんにちわ")` → voice output in Japanese pitch, not English.
- Overlapping calls → last call wins, no overlapping audio.
- On fresh Android without GTTS installed: still hears some audio (default TTS).

### Out of scope
- Multiple voice picker (use default Japanese voice).

### Linked files
- new: `mobile/src/lib/speech.ts`
- edit: `mobile/src/context/AppContext.tsx`

## Issue #058b — `expo-speech` TTS fallback notice when no ja-JP voice available
**Epic:** audio | **Type:** polish | **Priority:** P4 | **Size:** S
**Hard deps:** #038 | **Soft deps:** none | **Stream:** F | **Assignee:** ____

### Goal
When `Speech.getAvailableVoicesAsync()` returns zero voices with `lang.startsWith('ja')`, display a small notice to the user explaining that the Japanese voice was not found and providing a link to install the Google TTS engine (Android) or system settings. This can be ignored on iOS (always has a Japanese voice).

### Required deliverables
- On launch, check `getAvailableVoicesAsync()` and store a boolean in the `AppContext`.
- If `jaVoiceAvailable === false`, show a small banner at the top of any screen that has a speak button: "Japanese voice not installed — pronunciation may sound incorrect. Install Google TTS for best experience." (with link to Play Store).

### Validation / acceptance
- On an Android device without GTTS, notice appears after tapping a speak button.
- Dismissed state persists until next boot.

### Out of scope
- Auto-install of TTS engines.

### Linked files
- new: (no new files; banner integrated into AppContext logic)
